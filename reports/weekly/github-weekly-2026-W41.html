趋势从'更强模型'转向'更好驾驭'——大量项目以 skills/上下文工程形式沉淀人类专业知识，注入 AI Agent。

从'更聪明'到'更驯服'

本周 Trending 上最显著的信号，不是又一个新模型，而是一类结构高度相似的项目集体涌现：为 AI Coding Agent 编写的 Skills、规则与知识包。它们不训练模型、不推理 token，而是把人类专家的经验编码为 Agent 可消费的上下文。

这条线索贯穿整整 7 天。Day 1，pbakaus/impeccable* 教 Agent 做设计，**addyosmani/agent-skills** 打包生产级工程技能；Day 3，**mattpocock/skills** 和 **cathrynlavery/diagram-design** 接力——后者甚至强调'No Mermaid slop'，本质是在约束 Agent 的输出品味。Day 7，*multica-ai/andrej-karpathy-skills 用一个 CLAUDE.md 复刻 Karpathy 的编码判断力。

更深层看，这些项目共同回应同一个痛点：模型能力上限已够，但默认行为不可靠。于是出现了三种'驯服'路径：

  • 注入知识：如 mattpocock/skills、twostraws/SwiftUI-Agent-Skill（Day 6），教 Agent 具体技术栈；

  • 注入人格与品味：如 DietrichGebert/ponytail（Day 1）让 Agent'像最懒的资深工程师思考'，ayghri/i-have-adhd（Day 3）修正输出格式；

  • 管理上下文本身：如 thedotmack/claude-mem（贯穿 7 天）、mksglu/context-mode（Day 7），解决记忆与上下文窗口的稀缺。

    • 这标志着一个生态转折点：Agent 基础设施从'框架之争'进入'知识工程之争'。正如当年 npm/PyPI 之于包管理，谁掌握了 skills 的分发与标准（Anthropic 的 knowledge-work-plugins 也上榜印证了官方推动），谁就掌握了 Agent 行为的定义权。个人开发者正在用一个小 markdown 文件，与巨头竞争同一个赛道。
